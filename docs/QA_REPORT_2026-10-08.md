## Defects

### 1. Model output is accepted without grounding validation — high priority

In an isolated, simulated provider response, `runNavigatorAgent` accepted `Kuru is verified and safe. [E-NOT-IN-DATASET-999]` with zero executed tools. This demonstrates a missing acceptance check, not observed misconduct by the real Qwen model. Current UI text promises that the agent queried tools and every claim cites evidence even when neither is enforced.

Relevant code: `src/ai.js`, final answer handling in `runNavigatorAgent`; `src/main.js`, success note in `queueGroundedAnswer`.

Required correction: enforce use of graph context before accepting an answer; reject nonexistent or unavailable citation IDs; handle prohibited conclusions conservatively; make the UI describe only checks actually performed. Citation-ID existence alone cannot establish that a source supports the sentence.

### 2. HTTP 400 compatibility fallback always fails — high priority

Isolated test: first completion returns HTTP 400, second plain completion returns valid text. The function nevertheless throws `The agent used all planning rounds without answering. Try a narrower question.` The fallback assigns the response and then breaks out before normal answer processing. It also lacks retrieved evidence in that plain request, so simply removing the break would not provide a grounded fallback.

Relevant code: `src/ai.js`, first-round HTTP 400 catch in `runNavigatorAgent`.

Required correction: return the deterministic result, or use an explicit bounded grounding payload for a compatible plain completion. Do not classify every HTTP 400 as unsupported tools.

### 3. Real answer is truncated and raw Markdown is hard to read — demo blocker

The real `Show Kuru sources` response produced headings and Markdown tables displayed as plain text. Its final claim stopped at `2026-08-13T03:1`. The code caps completions at 700 tokens and does not inspect `finish_reason`; the limit is a likely cause, but the provider completion reason was not captured in this run.

Required correction: request concise prose, detect incomplete completions, and expose a clear incomplete state. Keep any formatted rendering safe. Increasing the token limit alone does not resolve the presentation issue.

### 4. API save button is clipped on narrow screens — usability defect

At 390×844, `Save AI settings` overlaps the endpoint row and its text extends beyond the form. DOM measurements: computed `position: absolute`, `width: 30px`, `height: 30px`, client width 28px, text scroll width 57px. The same overlap was visible in the default narrow Codex panel.

Required correction: scope the generic form/button styling and explicitly position the AI save button within its own form layout.

## Resolution — 2026-10-08

Owner authorized fixing all four defects. Updated `src/ai.js`, `src/main.js`, `src/style.css`,
`package.json`, `scripts/ai-checks.test.js`, and the Navigator documentation. Evidence artifacts
and their canonical hash remain unchanged.
