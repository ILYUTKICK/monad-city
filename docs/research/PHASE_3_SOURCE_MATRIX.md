## Interpretation rules

- Evidence status is attached to an exact claim, not to the whole project. These records must not turn a project into generically “verified.”
- `Claimed` below means attributable project-published documentation or site copy. It is not a wallet-signed owner claim and does not prove quality, safety, control of a contract, or current operation.
- `Observed` below means the named public artifact was directly inspectable: an official directory/registry entry, an explorer contract/event record, or an official launch record. Observation still does not imply endorsement or legitimacy.
- No source in this pass satisfies the current model’s requirements for `Attested`. Monad directory inclusion and the community-maintained protocol registry are useful observations, but they are not treated as scoped third-party attestations.
- No factual record is `AI-inferred`. AI-inferred output may be retained for discovery only and must never be used as claim support.
- `Source available` and `claim supported` are separate columns. A URL can be available while supporting only the fact that a publisher made a claim. Dynamic pages and mutable `main`-branch files need periodic re-retrieval.
- A contract page or transaction supports contract existence or a specific event. It does not, by itself, support “safe,” “active,” “current,” “official,” or “integrated.” Time-bound activity requires a defined window and fresh event retrieval.
